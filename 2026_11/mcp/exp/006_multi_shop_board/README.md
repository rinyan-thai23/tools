# 006 複数店舗の比較ボード（本部向け・月額想定）

- 日付：2026-11-27　／　実費：**約$0.15**（20支店のボード$0.102＋最初の試行$0.051）　／　状態：見本＋LPまで完了
- 区分：**A（DataForSEOだけで完結）**。口コミの読み取りはAI（Claude）
- 一言：同じチェーンの支店（20店）を横に並べて、「どの店が、なぜ負けているか」を1枚で見せる。

## 誰の、どんな悩みか
複数の店舗（支店）を持つ本部・オーナー。支店ごとの口コミ・順位を、1店ずつ見て回るのは大変で、**どの支店に手を入れるべきか**が分からない。
喜ばれる理由：自動で集めて、注意の印が多い順に並べ、原因の仮説まで読める。

## 強引チェック
1. 悩みは本当にあるか：**仮説**（本部に聞いていない）。既存の口コミ管理ツール（口コミコム、MEOアナリティクスなど）は、**複数店舗対応を売りにしている**（007）。**競合あり**
2. APIなしで価値は成り立つか：成り立つ。価値は「並べて、印を付けて、原因を読む」こと
3. 既存より何が良いか：既存ツールは月額のSaaS。**1回限りの調査レポート**（スポット）として出せる点が違う可能性。**未確認**
- **強引度：中〜高**（既存の複数店舗向けツールが多い。差は小さいかもしれない）

## 何をどのようにしたか
`tool/board.mjs`（設定：`tool/config.anytime.json`）が、1コマンドで次を行う。
1. **支店を集める**：最初は `business_listings/search`（店名で絞る）→ **店名にスペースがある支店が漏れて3店しか取れなかった**。**地図検索（`serp/google/maps`・1回$0.002）で近くの支店を集める**方式に変更 → **20支店**
2. **各支店の口コミ**を並列で取得：新しい順30件＋評価の低い順10件（`google/reviews`）
3. **各支店の場所で「ジム」と検索した順位**（`serp/google/maps`・1回$0.002×20）
4. 集計：評価、直近6か月の口コミ数、星1〜2の割合（新しい順）、低評価への返信率、低評価の話題（キーワード辞書）
5. **注意の印をルールで付けて並べる**（`tool/build_table.mjs`）：評価3.9未満／星1〜2が2割以上／低評価（3件以上）への返信が半分未満／お店の場所でも7位以下／直近6か月の口コミが7件以下
6. AI（Claude）が、印の多い支店の低評価を読み、原因をまとめた
7. LP（`lp/index.html`）：チェーン名・支店名を伏せ、記号（A〜T）で表示

## 結果（東京西部の24時間ジム・20支店）
- **注意の印がある支店：12 / 20**。印が最も多い支店A（評価3.4）は、4つの印
- **評価の幅：2.7〜4.6。** 低評価に1件も返信していない支店が3つ、100%返信の支店が9つ（**支店任せで、ばらつく**）
- **原因は支店ごとに違う（AIが読んだ）：** A＝改装後の不評（照明・無料の水の撤去・シャンプー廃止）／B＝シャワーのカビが直らない／C＝狭い・マシンの不調放置・ネット不通／D＝浄水器なし・害虫／E＝解約後も引き落とし／F＝地下で狭く、マシンの種類が少ない
- **本部への示唆：** 設備の標準が支店で不統一（シャワー室のシャンプーの有無）／**返信のルールを本部で決める**／空調（スタッフ不在の時間帯）／解約・請求の仕組み

## 気づき・弱点
- **「星1〜2の割合」は、最新30件のうちの割合。** 1件で3％動く。件数の少ない支店は、ゆれが大きい
- **「直近6か月の口コミ数」は、最新30件のうちの数。** 読み違いで、一度、表を作り間違えた（「30件中」を「30件以上」と読み違え）→ 修正した
- **順位は、1時間でも動く**（004）。月次で変化を見せるには、ゆれを前提にする必要がある
- **店名での絞り込み（`business_listings` の `title`）は、支店が漏れる。** 地図検索のほうが、支店を拾える
- 口コミは利用者の主張で、事実の確認はしていない。**支店名を出して順位をつけると、支店の反発を招く**ので、本部の会議用に限定するのが安全
- 見本は1チェーン（20支店）だけ。**需要は未確認。既存ツールとの差も未確認**
