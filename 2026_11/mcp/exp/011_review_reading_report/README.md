# 011 口コミ読解レポート（店主向け・スポット／月額）

- 日付：2026-11-26　／　実費：**約$0.02**（取得テスト一式）　／　状態：見本＋LPまで完了
- 区分：**A（DataForSEOだけで完結）**。口コミの取得はDataForSEO、読み取りはAI（Claude）
- 一言：Googleマップの口コミを読んで、褒められている点・不満の型・返信が必要な口コミ・返信の下書き・次の一手を1枚にする。

## 誰の、どんな悩みか
歯科・美容室・クリニックなど、口コミが集患に効く業種の店主。口コミを全部読んで整理する時間がなく、低評価への返信も滞りがち。
喜ばれる理由：読んで整理する手間がなくなり、「どれに返信するか」「何を直すか」が1枚で分かる。

## 強引チェック（`IDEAS.md` の3つの問い）
1. 悩みは本当にあるか：口コミが集患で重要という調査はある（元調査は未確認）。**返信の手間は仮説**（店主に聞いて確かめる）
2. APIが無くても価値は成り立つか：成り立つ。価値の本体は「読んで整理すること」。APIは口コミ本文を集める材料
3. 既存の代わりより何が良いか：口コミ管理・返信代行ツールがあるはず（**未調査**）。差は「読み解いて次の一手を1つに絞ること」だけかもしれない
- **強引度：低〜中**（需要の確認が残っている）

## 何をどのようにしたか
1. **使えるAPIを調べた**（無料）：`business_data/google/reviews/task_post`（依頼）→`task_get`（結果）の2段。`live` はない。料金は「10件ごと」
2. **見本の店（口コミ18件の美容室）で取った**：`depth=20` で全18件。費用 **$0.0015**。本文・星・時期・店からの返信の有無・投稿者情報つき（`tool/fetch_reviews.mjs`）
3. **大きな店でも試した**（口コミ1,180件の歯科）：関連順100件（$0.0075）、星の低い順40件（$0.003）
4. **集計**（`tool/analyze.mjs`・費用0）：星の分布、時期別の平均、返信率、話題のキーワード数
5. **AI（Claude）が本文を読んで**、褒められている点・不満の型・返信の下書きを書いた
6. **見本レポート入りのLP**を作った（`lp/index.html`）。店名・スタッフ名・投稿者名は伏せ

## 結果（見本）
- **美容室（18件・星3.7）：** 2年より前10件は平均4.4、直近2年8件は平均2.8。低評価7件は「仕上がり2・予約会計3・マナー1・本文なし1」。返信のない低評価が2件（うち1件が本文つきの2か月前の星1）
- **歯科（1,180件・星4.3）：** 見本100件の星1は22件。低評価24件のうち17件が自費診療・費用に触れ、**返信は0件**（最低評価の40件では6件に返信あり）

## 気づき・弱点
- **取得が0件で返ることがある**：新しい順100件の依頼が、成功扱いで0件・料金だけ請求された（同じ店の関連順100件は成功）。**0件のときは自動でやり直す仕組みが要る**
- 口コミ本文の読み取りは、**この回はAI（Claude）がセッション内で読んだ。** 製品にするときは、Claude APIで自動化する。1回あたりの読み取り費用は未測定（18件で数千トークンの見込み）
- 話題の数え方は、キーワードによる目安（1件が複数の話題に入る）。AIの読みで補った
- **関連順の100件は抜き出し**であり、全体の傾向とは限らない
- 口コミ本文には、スタッフ名・投稿者名が入る。**レポートや公開物には出さない**（見本は伏せ字）
- 見本は2店だけ。他の業種・他の店で、「型」の切り出しが妥当かは未確認
- **需要は未確認**。返信が滞って困っている店主が本当にいるかは、聞くまで分からない

## 判断
- **区分A・強引度は低〜中。** 取得の原価は無視できるほど低く、AIの読み取りが価値になる。**次は、店主・代行業者に見せて反応を聞く**（需要の確認）。既存の口コミ管理ツールの調査（007の一部）も必要
- 月額版（毎月の新しい口コミ）にするなら、順位とは違い、**口コミは新しく増えるだけなので、004のゆれの問題は起きない**
