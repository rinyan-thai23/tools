# 016 業種×街の「不満・期待」口コミ調査レポート（業界の人向け・スポット）

- 日付：2026-11-26　／　実費：**$0.144**（32院・606件。約1分、全自動）　／　状態：見本＋LPまで完了
- 区分：**A（DataForSEOだけで完結）**。取得・集計は自動、読み取りはAI（Claude）
- 一言：「この業種・この街のお客さんは何に不満で、何を求めているか」を、口コミ数百件から読み取って1枚にする。

## 誰の、どんな悩みか
**買う人（業界の人）：** 開業支援・業界コンサル・医療機器や材料のメーカー・業界メディア。お客さん（患者・利用者）の本音を知りたいが、調査会社は時間も金もかかり、自分で口コミを読むのは大変。
**使い道：** 開業時に何を優先するか、商品・サービスの開発の方向、HPや広告の言葉、記事のネタ。
喜ばれる理由：1回作れば、複数の相手（開業者・メーカー・メディア）に提案できる（横展開）。

## 強引チェック
1. 悩みは本当にあるか：**仮説**。業界の人が患者の本音を知りたいのは自然だが、誰がお金を払うかは聞かないと分からない
2. APIなしで価値は成り立つか：成り立つ。価値の本体は「読み取って、使い道を示すこと」。APIは材料
3. 既存より何が良いか：口コミ分析ツール（クチコレ等）は店ごとの分析が中心に見える。**「業種×街」の横断レポート**は未確認（007）。市場調査会社・アンケート調査が代わりになる可能性
- **強引度：中**

## 何をどのようにしたか（自動化の流れ）
`tool/market_reviews.mjs` が、1コマンドで次を実行する。**人が手でやると回らない部分を自動にした。**
1. 総数の確認（`business_listings/search`・limit=1）
2. **小さなかたまり（8院）を、ランダムな位置から4回取って、32院を選ぶ**（人気の似た店ばかりになるのを避ける。選んだ位置を記録）
3. 各院の口コミを**並列**で取る：新しい順20件＋評価の低い順10件（`google/reviews`）。**0件で返ったら並び順を変えてやり直す**（今回は不要）
4. 重複を除く（同じ口コミが新しい順と低い順の両方に出る）
5. 集計：星の分布、本文なし、返信率、話題の割合（業種ごとのキーワード辞書：`config.tokyo_dental.json` の `topics`）
6. **読み取りパケット**を作る（星1〜2から50件・星4〜5から20件を無作為に抽出）
7. **AI（Claude）が読み取りパケットを読んで、不満・期待の「型」にまとめる**（今回はセッション内で実施。製品にするときは、Claude APIで自動化）
8. 見本レポート入りのLP（`lp/index.html`）

## 結果（東京の歯科・評価4以上・口コミ10件以上の32院）
- 星の分布（新しい順551件）：星5 77%、星1〜2 12%。本文なし19%
- **星1〜2の口コミに、医院が返信した割合：31%（7割は返信なし）**
- AIが読んだ不満の型（星1〜2の本文95件から50件を読んだ目安）：**受付・電話の応対 約28%、治療の結果・見落とし 約28%、説明不足 約16%、待たされる・予約が取れない 約12%、医師の態度 約10%、痛み・雑な扱い 約8%、HPと実際の食い違い 約6%**
- 褒められている理由（星4〜5の20件）：説明が分かりやすい、親切、技術、清潔・個室、立地・当日予約、痛みが少ない
- **「説明・カウンセリング」は、星4〜5の46%で出て、星1〜2では29%**。強みにも弱みにもなる話題
- **HPと実際の食い違い**（実際にしていない診療がHPにある、担当医制がHPにない）が出ていた → 制作会社に使える

## 気づき・弱点
- **「歯科全体」ではない。** 評価4以上の院に絞っている。不満はもっと多い可能性がある
- **業種カテゴリのノイズ：** `dental_clinic` に、眼科の口コミが混ざっていた（高評価20件の読み取りの中で確認）。混ざる割合は未測定
- **不満の型の件数は、AIが50件を読んだ目安。** 手作業の読み取りで、再現性は未確認。製品化では、Claude APIで全件分類し、件数を安定させる
- 話題のキーワード辞書は、**業種ごとに作り直す必要がある**（今回は歯科用）
- 半径20kmが県をまたぐ（埼玉の八潮・川口が含まれる）。都道府県で分ける処理は未実装
- **規約・個人情報・著作権は、まだ確認していない**（口コミ本文は集計・言い換えにとどめ、投稿者名・医院名は出さない）
- 需要は未確認（業界の人に聞いていない）
