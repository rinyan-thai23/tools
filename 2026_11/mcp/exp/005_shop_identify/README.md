# 005 店の特定の改善（同名・チェーン店の取り違え防止）

## 誰の・なぜ
- 誰の：自分たち（002 診断メーカーの安全性）。診断を渡す相手は「自分の店」の結果を期待している
- 困りごと：同じ名前のお店・チェーンの支店だと、別の店を診断してしまい、信用を失う

## 仕組み（`lib/identify.mjs`）
地図検索の上位8件を点数づけ：店名一致 +3（部分一致 +2）、住所のヒント +3、電話下8桁 +5。
確信度：high（5点以上かつ2点差）／medium／low。同名が複数で high でなければ low。
002 の `generate.mjs` に組み込み済み（`--identify-only` で確認だけ、住所・電話のヒントを渡せる）。
確信度が high 以外の時は、診断書に「対象店の確認」欄を出す。

## テスト（5件・合計 $0.02〜0.03）
| ケース | 結果 |
|---|---|
| 一意な店名 | medium（正しい店） |
| チェーン・ヒントなし | low（候補を並べる） |
| チェーン＋住所ヒント | medium（正しい支店） |
| ありふれた店名 | low |
| ありふれた店名＋ヒント | medium |
意図どおり。結果は `data/test_results.json`。

## 強引度
低。需要の話ではなく、品質の安全弁。診断を送る前に人が1回見るなら、これで十分。
